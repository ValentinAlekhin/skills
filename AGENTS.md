# Работа с репозиторием

Этот репозиторий содержит личные скиллы агента. Каждый скилл находится в своей
папке с `SKILL.md`; необязательные ресурсы и `agents/openai.yaml` относятся
к тому же скиллу. Правила стека внутри `mvp/` применяются к создаваемым с его
помощью приложениям.

## Изменения и проверки

- Сохраняй скиллы самодостаточными. Записывай рабочие правила, без описания
  проектов, приведённых пользователем в качестве примера.
- При изменении названия или назначения скилла обновляй каталог в `README.md`
  и соответствующие UI-метаданные.
- Проверяй изменённые скиллы через `quick_validate.py` из установленного
  `skill-creator`. Если для валидатора нужен PyYAML, можно запускать его через
  `uv run --no-project --with pyyaml python <путь-к-quick_validate.py> <скилл>`.
- Перед коммитом выполняй `git diff --check`.
- Используй Conventional Commits: `<type>[optional scope][!]: <description>`.
  Для изменения `mvp/` указывай scope `mvp`, когда это помогает описанию.

## Установка и обновление агента

Пользовательская установка `mvp` — символическая ссылка
`~/.agents/skills/mvp` на папку `mvp/` этого checkout. Это единственная установка
скилла; ссылка отражает рабочую копию, включая незакоммиченные изменения.

После каждого коммита в этом репозитории проверяй, что установленный `mvp`
указывает на текущую папку скилла и его файлы доступны агенту. Отдельное
копирование после коммита не требуется: ссылка уже отражает изменения.

Если установки нет, создай её из корня репозитория:

```sh
mkdir -p "$HOME/.agents/skills"
ln -s "$(git rev-parse --show-toplevel)/mvp" "$HOME/.agents/skills/mvp"
```

Если путь уже занят отдельной копией или другой ссылкой, сначала изучи её
содержимое и сохрани локальные изменения перед заменой. При перемещении checkout
обновляй ссылку на новое расположение. Сообщай пользователю, если установка
или проверка обновления не удалась.
